# MAX30102 and RTC fix — v10

## What changed

### MAX30102

- I2C3 bus recovery before probing devices: release SDA with up to nine SCL pulses and generate STOP.
- I2C analog filter enabled.
- MAX30102 initialization retries three times.
- LED current increased from `0x1F` to `0x3F` for both Red and IR.
- Finger IR threshold reduced from `50000` to `15000`.
- Finger-loss debounce increased from 4 to 15 FIFO samples.
- The screen now distinguishes:
  - `MAX30102 MISSING`: no ACK at address `0x57`.
  - `BAD SENSOR ID`: a device replies at `0x57`, but PART_ID is not `0x15`.
  - `I2C BUS ERROR`: communication failed after detection.
  - `SENSOR TIMEOUT`: reset did not complete.

### Date and time

- The RTC is read every second.
- If RTC data is invalid or earlier than the firmware build timestamp, the RTC is initialized automatically from `__DATE__` and `__TIME__` generated by STM32CubeIDE.
- If the RTC module is absent, the UI still runs a software clock starting from the build timestamp. This fallback does not survive a power cycle, but the displayed time remains live while the board is powered.
- Basic time registers are compatible between DS1307 and DS3231.

## Mandatory wiring

| Signal | STM32F429I-DISCO | MAX30102 | RTC |
|---|---|---|---|
| SCL | PA8 | SCL | SCL |
| SDA | PC9 | SDA | SDA |
| Supply | 3.3 V | VIN/VCC | 3.3 V for DS3231 |
| Ground | GND | GND | GND |

Test the MAX30102 alone first. Disconnect the RTC until the screen changes from
`MAX30102 MISSING` to `PLACE FINGER`.

A classic DS1307 normally requires about 5 V. Many DS1307 modules pull SDA/SCL
up to their VCC, so they must not be connected directly to the STM32/MAX30102 bus
when powered from 5 V. Use a bidirectional I2C level shifter or use a DS3231
module powered at 3.3 V.

## Expected sequence

1. `MAX30102 MISSING`: check power/wiring/address.
2. `PLACE FINGER`: sensor communication is working.
3. `MEASURING...`: finger detected; keep it still for about 4 seconds.
4. BPM and SpO2 values appear.
